The four supplied images were layout references, not product data. The Map tab shows a full sample map with one “Start a report” action; pole markers and location editing appear only in the report flow. On desktop, the report page shows the ArcGIS sample map next to a photo dropzone. Uploading a photo requests current GPS and offers one nearby sample streetlight for explicit confirmation. “Choose another” opens a single correction section; manual coordinates, pole number and a map pin remain closed until the resident opens that backup section. On phones, camera and gallery are first, followed by map and review. Navigation reads Map, Report, Saved. The header stays visible while scrolling.

The Saved screen continues to show browser-local drafts without accounts. It does not display the sample “submitted,” “in review” or “needs attention” statuses in the references, because this app has no provider delivery or status integration. Every draft remains `not_sent`; photo data remains in this browser. The UI never claims to identify a pole from image content. The nearby suggestion comes from confirmed location and the fixed DEMO pole adapter. A photo from another place needs manual location correction.

No server contract, storage schema, dependencies, provider data or report submission behavior changed. The bounded CenterPoint JSON exporter stays a separate research tool pending data-use approval. The official map link remains available.
